# 04. Содержание: задачи, уроки, разборы, словарь

Содержание лежит в `src/GoEngine.Problems` и редактируется **файлами**, а не кодом:

| Что | Где | Формат | Сколько |
|---|---|---|---|
| Задачи | `Problems/ts-*.sgf` | SGF + метаданные | 36 |
| Уроки | `Lessons/go-*.json` | JSON | 12 |
| Учебные партии-разборы | `Games/game-*.json` | JSON | 8 |
| Словарь терминов | `Glossary/glossary.json` | JSON | ~40 терминов |

Загрузка и разбор — `ProblemSgf`, `LessonJson`, `ReviewJson`, `GlossaryLibrary`; проверка —
`ProblemLibrary`, `LessonLibrary`, `ReviewLibrary`.

## Задача (`ts-*.sgf`)

Пример (реальный файл, сокращён):

```sgf
(;GM[1]FF[4]CA[UTF-8]SZ[9]KM[5.5]
  GN[Поставить белую группу в атари]
  GC[Ход чёрных. Поставить белую группу в атари: покажите два хода.]
  GE[reference] GD[20] GW[3] SO[goproblems.ru/36elem/ts0.htm, задача 001]
  PL[B] GT[ea]
  AB[dd]AB[ed]AB[fd]... AW[ce]AW[ge]...
  ;B[da];W[ca];B[ga])
```

| Свойство | Значение |
|---|---|
| `SZ` | размер доски (9/13) |
| `KM` | коми |
| `GN` | название задачи (видно игроку) |
| `GC` | цель словами («Ход чёрных. …») |
| `GE[reference]` | задача из источника, эталонная линия; машинного доказательства исхода нет |
| `GD` | номер/сложность в источнике (см. `ProblemSgf`) |
| `GW[3]` | окно для проверки цели (сколько ходов решающего считается) |
| `SO` | источник, для сверки с оригиналом |
| `PL[B]` | чей первый ход |
| `GT[ea]` | целевая точка/условие цели (`ProblemGoal`) |
| `AB`/`AW` | расстановка перед задачей |
| `;B[..];W[..]` | эталонная линия решения |

**Критично:** координаты SGF читаются с переворотом строк (`ProblemSgf.ParsePoint`): SGF-буквы
и подписи доски различаются. Цель `GT` задаётся в подписях доски, а линия — в SGF;
сверяйте результат в приложении (см. `02-go-domain.md`).

Правила содержания задач:

1. Цель должна соответствовать тому, что **реально доказывает** линия. Если снятия нельзя форсировать —
   не пишите «убить», пишите «разрушить глазную форму», «зажать», «стеснить».
2. Текст не должен называть ответ (координату, точку) до решения.
3. Число ходов в цели («покажите два хода») должно совпадать с числом ходов решающего в линии.
4. Посторонний ход обязан отклоняться, правильный — приниматься.

## Урок (`go-*.json`)

```json
{
  "id": "go-01",
  "title": "Правила и цель игры",
  "summary": "Доска, ход на пересечениях, дыхания, плен и территория",
  "source": "…",
  "size": 9,
  "steps": [
    {
      "kind": "explain",
      "title": "Доска и камни",
      "text": "…",
      "position": { "toMove": "B", "black": [], "white": [], "highlight": [] }
    },
    {
      "kind": "task",
      "title": "Первый ход",
      "text": "…",
      "position": { "toMove": "B", "black": [], "white": [], "highlight": ["ee"] },
      "answer": ["ee"],
      "hint": "ee",
      "success": "Верно! …",
      "failure": "…"
    }
  ]
}
```

| Поле | Смысл |
|---|---|
| `kind` | `explain` (объяснение) или `task` (задание) |
| `position` | расстановка: `toMove`, `black`/`white` — точки, `highlight` — подсвеченные точки |
| `answer` | допустимые ходы (список) |
| `hint` | точка подсказки; должна совпадать с принимаемым ходом |
| `success`/`failure` | отклик; «Верно! …» — причина, а не только оценка |

Правила содержания уроков:

1. Утверждение о правилах или форме должно быть верным (ноби — не соединение; косуми можно разрезать;
   C7 — третья линия; пасть тигра — вход невыгоден, а не невозможен).
2. Координаты — в подписях доски (строка 1 сверху, буквы без `I`).
3. Подсказка ведёт к верному ходу; неверный ход объясняется **по причине**, а не «попробуйте ещё».
4. Один урок — одна тема; `summary` — что игрок узнает.

## Партия-разбор (`game-*.json`)

```json
{
  "id": "game-01",
  "title": "9×9: углы, расширение и снятие групп",
  "size": 9,
  "komi": 5.5,
  "players": { … },
  "result": "…",
  "moves": ["df", "ff", "ed", …],
  "notes": [
    {
      "before": 0,
      "title": "Начало: углы на третьей-четвёртой линии",
      "text": "…",
      "quiz": {
        "answer": ["df", "cc", …],
        "hint": "df",
        "success": "Верно! …",
        "failure": "…"
      }
    }
  ]
}
```

| Поле | Смысл |
|---|---|
| `moves` | партия в SGF-координатах |
| `notes[].before` | к какому номеру хода относится заметка (0 — до первого хода) |
| `quiz.answer` | список допустимых ходов вопроса |
| `result` | итог партии; числа должны сходиться с правилами (система счёта — см. [02-go-domain.md](02-go-domain.md)) |

Правила содержания разборов:

1. Вопрос стоит **за ту сторону, чей ход**; список ответов — только её ходы.
2. Заголовок и текст заметки **не называют ответ** (спойлер) — проверялось QA отдельно.
3. Комментарий не утверждает «соединяю», если группа одна, и «разрезаю», если ход лишь примыкает
   к двум группам.
4. Итог партии и `result` согласуются с выбранной системой счёта.

## Словарь (`glossary.json`)

```json
{ "name": "Атари", "original": "当たり",
  "text": "Положение, когда у камня или группы осталось одно дыхание…",
  "lessons": ["go-01", "go-03"] }
```

Термин показывается в словаре и подсказкой в уроке; `lessons` — где термин встречается.

## Как добавить материал

1. Задача: создайте `Problems/ts-0NN.sgf` по образцу, зарегистрируйте в `ProblemLibrary`,
   добавьте проверку в `ProblemContentTests` (цель ↔ финальная позиция: дыхания, глаза, снятия).
2. Урок: `Lessons/go-0NN.json`, зарегистрируйте в `LessonLibrary`; проверьте шаги тестом
   (`LessonTextTests` — координаты и формулировки).
3. Партия: `Games/game-0NN.json`, зарегистрируйте в `ReviewLibrary`; проверьте вопросы
   (сторона, спойлер, допустимые ответы).
4. Термин: допишите в `glossary.json`, укажите уроки.
5. Прогоните `dotnet test` (домен) и `./check.ps1`: содержание проверяется тестами, а не глазами.

## Что уже проверяется тестами

- `ProblemContentTests` — 10 критических задач: финал линии совпадает с названием (дыхания/глаза);
  число ходов в цели; цвет снятых камней.
- `LessonTextTests` — координаты и формулировки уроков.
- `ProblemShapeHighlightTests`, `ShapeSetGroupTests`, `MoveShapeTests` — формы и подсветка всех камней.
- `MoveDescriberVarietyTests`, `MoveDescriberTests` — тексты разборов не шаблонные и не лгут.
