# 03. Приложение: оболочка, экраны, раскладка, рендер

## Слои и головы

`GoEngine.App` — **библиотека** интерфейса: виды, модели представления, сервисы, рисование.
`GoEngine.App.Desktop` и `GoEngine.App.Android` — **головы**: точка входа, платформенные пакеты,
проверочные режимы. Голова ссылается на библиотеку, библиотека на головы — никогда.

## Оболочка и навигация

`ShellView` — единственная оболочка на процесс (создаётся один раз; повторное создание — источник
классического падения «already has a visual parent»). Внутри — четыре раздела:

| Раздел | Вид | Модель |
|---|---|---|
| Партия | `BoardView` | `MainViewModel` |
| Задачи | `ProblemView` | `ProblemViewModel` |
| Обучение (уроки/партии/словарь) | `LessonView`, `ReviewView`, `GlossaryView` | `LessonViewModel`, `ReviewViewModel`, `GlossaryViewModel` |
| Меню | `AppMenuView`, `SettingsView`, `AboutView`, `UpdateBanner` | `ShellViewModel`, `UpdateViewModel` |

`LoadingView` показывается первым кадром, подготовка (модели, настройки, установка) идёт в фоне.
Не переносите подготовку в конструктор окна: игрок увидит пустой экран вместо загрузки.

## Виды: правила слоя

- Вид не хранит игровое состояние: всё в модели представления (`MainViewModel` и др.).
- Вид не считает правила и счёт: только форматирует то, что дала модель.
- Вид не открывает окна напрямую: навигация — через события/модель оболочки.
- Один экран — один файл `.axaml` + code-behind, где допустимы только обработчики ввода и
  элементы, которые нельзя выразить привязками.
- Публичные члены — с русскими XML-доками (warnings-as-errors).

## Модели представления

| Модель | Ответственность |
|---|---|
| `MainViewModel` | партия: ходы, пас, отмена, территория, счёт, итог, часы, настройки партии |
| `ProblemViewModel` | задача: линия решения, подсветка, вердикт, формы, подсказка |
| `LessonViewModel` | урок: шаги, задания, прогресс, подсказки |
| `ReviewViewModel` | разбор партии: заметки, вопросы, пояснения к ходу |
| `ShellViewModel` | разделы, меню, общий контекст |
| `GlossaryViewModel`, `UpdateViewModel` | словарь и обновление |

`MainViewModel` — самая большая модель (несколько тысяч строк). Начинайте с публичных свойств
и `NotifyAll()`: он перечисляет всё, что вид рисует; забытое свойство = «экран не обновился».

## Раскладка и мобильная версия

`BoardLayoutRules.DecideLayoutFor(width, height, isPhone)` — единое место решений о раскладке;
`BoardPanelLayout` — общие правила панели (партия, задачи, обучение), чтобы телефонные правила
не дублировались в трёх местах. `BoardHeightShare` — доля высоты под доску.

Мобильные особенности, на которые уже наступали:

1. **Портрет** закреплён в `MainActivity`; экран 445×1010 dp — целевой телефон.
2. **Цели нажатия ≥ 64 dp**, если элемент у нижнего края: на Android отрисовка и касания смещаются
   на высоту статус-бара (D-107). Мелкие цели (<48 dp) в нижней зоне — риск «не нажимается».
3. **Строка статуса/сообщения** не должна менять высоту панели: иначе доска «прыгает» на ~29 px.
   Сообщения — оверлеем или закреплённой строкой с резервом места.
4. **Вердикт и сообщения** — в закреплённой полосе над кнопками (2 строки + многоточие), полный
   текст — в прокрутке: иначе длинный разбор вытесняет «Задача решена» за экран.
5. **Прокрутка** начинается сверху при смене шага/задачи (`PanelScroll.Home`).
6. **Координаты на камнях** рисуются на подложке цветом доски: тёмная подпись на чёрном камне
   не читается.

## Рендер

`BoardRenderer` (Skia) рисует доску, камни, подсветку, последний ход, формы, разметку территории
и координаты. Геометрия — `BoardGeometry` (щелчок ↔ точка), анимация — `StoneAnimation`,
звук — `StoneSound`, значки форм — `ShapeBadge`.

Правила:

- Рисование и попадание щелчка обязаны совпадать геометрией из одного источника (`BoardGeometry`).
- Новые элементы (подписи, значки) проверяются тестом-картинкой: `BoardCoordinateRenderTests`.
- Не рисовать «поверх» без подложки на тёмных камнях и в углах.

## Сервисы

| Сервис | Зачем |
|---|---|
| `AppSettings` + `SettingsStore` | настройки партии и приложения, JSON рядом с данными |
| `ProgressStore` + `StudyProgress` | прогресс уроков/партий (файл `progress.json`) |
| `ScoringState` | снимок счёта и мёртвых групп |
| `GameClock` | часы партии (старт, пауза, стоп) |
| `ModelInstaller`/`IModelSource` | копирование и установка ONNX-моделей на Android |
| `AppDataPaths` | единые пути данных (настройки, прогресс, логи, модели) |
| `BoardLayoutRules`/`PlatformMetrics` | раскладка и размеры платформы |
| `AppLog`/`CrashReporter` | структурные логи и отчёт о падении |

Время — только через `TimeProvider`; в тестах `FakeTimeProvider`.

## Запуск, загрузка, падения

1. `Program.Main` включает логи и обработчик падений — **до** создания окна.
2. `LoadingView` показывается сразу; подготовка идёт в фоне (копирование моделей, ONNX).
3. После подготовки создаётся `ShellView` (один на процесс).
4. Падение пишет лог и файл-признак; следующий запуск показывает «Прошлый запуск завершился сбоем».

Если приложение «висит на стартовой картинке» — почти всегда виноваты правки в подготовке/создании
оболочки. Проверяйте на живом устройстве до выпуска (см. `06-release-and-quality.md`).

| раскладка на телефоне | `Services/BoardLayoutRules.cs`, `Views/BoardPanelLayout.cs` |
| рендер доски | `Rendering/BoardRenderer.cs`, `BoardGeometry.cs` |
| настройки | `Services/AppSettings.cs`, `Views/SettingsView.axaml` |
| режим проверки без окна | `App.Desktop/Diagnostics/*`, `check.ps1`, CI |
