# 11. Роли агентов и процесс изменения кода

**Дата:** 2026-11-11. **Статус:** обязательно для всех изменений продукта (R-012).

Правило сессии: ни один diff не считается закрытым, пока его не проверили три независимые роли.
Lead координирует, коммитит и выпускает, но не заменяет ревью и живой прогон.

| Роль | Что делает | Что не делает |
|---|---|---|
| **coder** | Реализация по задаче (код + тесты), self-check сборки/тестов, отчёт с файлами и числами | Не коммитит и не пушит сам; не проверяет свою работу как единственный судья |
| **reviewer** | Независимое ревью КАЖДОГО diff: корректность, регрессии, полнота и поведенчность тестов, соответствие REQUIREMENTS/D-решениям. Вердикт: чисто / блокеры / замечания | Не правит продукт; не оправдывает уже написанное |
| **tester** | Живая матрица на реальном Android (CTR-LX1) и Desktop: репро R-001 3/3, Back по всем разделам, темы light/dark, сеть (discovery, join, нигири, 30/10, обрыв/терминал, protocol mismatch), Recents/cold start. Скриншоты, логи, PASS/FAIL | Не правит продукт; не закрывает пункт без воспроизводимого PASS |
| **Lead** | План, память проекта, интеграция, сборки/релизы, финальная приёмка; привлекает роли на каждый diff | Не выпускает релиз без ревью и живой проверки |

**Порядок:** задача → coder (код/тесты) → reviewer (дифф) → исправления → tester (живая
матрица на релизной сборке) → Lead (docs/REQUIREMENTS/STATE/журнал + релиз).
Исключений для «мелких» фиксов нет: мелкий фикс — тот же цикл, только короче.
