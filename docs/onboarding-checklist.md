# 09. Чек-лист онбординга (первая неделя)

Цель: к концу недели вы понимаете архитектуру, умеете собрать/проверить проект,
выпустить сборку по инструкции и сделали первое осмысленное изменение с тестом.

## День 1 — запустить и увидеть

- [ ] Прочитать `PROJECT.md` (границы, стек, как проверять) и `docs/README.md`.
- [ ] Установить .NET 8 SDK; `dotnet --version` = 8.x.
- [ ] `dotnet build src/GoEngine.sln` — зелёная сборка.
- [ ] `dotnet run --project src/GoEngine.App.Desktop` — поиграть 10 минут: партия, задача, урок.
- [ ] `./check.ps1` — увидеть полный цикл проверки (или `./check.sh`).
- [ ] Прочитать `docs/05-development.md` (команды, общие ресурсы, типовые проблемы).

## День 2 — архитектура и домен

- [ ] `docs/01-architecture.md`: слои, проекты, потоки «ход игрока», «счёт», «запуск».
- [ ] `docs/02-go-domain.md`: координаты и переворот SGF, легальность, счёт, жизнь/смерть.
- [ ] Прочитать `GO_RULES.md` (правила и раздел 13 — тестовые позиции).
- [ ] Найти в коде: `GameState.TryPlay`, `Scorer`/`FinalScore`, `ProblemSession`, `LessonSession`.
- [ ] Прогнать один доменный тест и прочитать его как документацию.

## День 3 — интерфейс

- [ ] `docs/03-application.md`: оболочка, разделы, модели, рендер, мобильные правила.
- [ ] Открыть `BoardView.axaml` + `MainViewModel`: найти, как обновляется панель (`NotifyAll`).
- [ ] Запустить `--render` и посмотреть PNG: понять, что рендер один для экрана и проверок.
- [ ] Пройти по `check.ps1`: какие режимы что проверяют.

## День 4 — содержание

- [ ] `docs/04-content.md`: форматы SGF/JSON, правила содержания, спойлеры, координаты.
- [ ] Открыть одну задачу `ts-*.sgf`, один урок, одну партию — сверить с приложением.
- [ ] Запустить `ProblemContentTests`, `LessonTextTests`.

## День 5 — первое изменение

Варианты (выбрать с ведущим):

1. Исправить известную проблему из `docs/08-known-issues.md` (например, текст `ProblemTexts.Solution`).
2. Добавить проверку содержания (страж от спойлеров с верной картой координат).
3. Добавить/уточнить XML-док или тест на непокрытое место в `Core`.

Порядок: задача в `TASKS/` → тест → код → `./check.ps1` → решение `D-0xx` (если меняется поведение) →
коммит с сообщением по сути.

## День 6–7 — выпуск под наблюдением

- [ ] Прочитать `docs/06-release-and-quality.md` и `07-decisions-and-history.md`.
- [ ] Пройти чек-лист выпуска на тестовой ветке/драфте.
- [ ] Освоить смоук на эмуляторе: установить APK, запустить, пройти партию/задачу/урок.
- [ ] Разобрать с ведущим 2–3 решения из `DECISIONS.md`, чтобы понять стиль аргументации.

## Договорённости, которые нужно принять сразу

1. Слои не нарушать; ожидаемые ошибки — `Result`.
2. Сборка/тесты — по очереди; живые проверки — под блокировкой; чужие процессы не убивать.
3. Любое поведение — с тестом; любое решение — с `D-0xx`.
4. Не выпускать без смоука на устройстве (урок 0.2.105).
5. Содержание проверяется по правилам и позиции, а не «на глаз».

## Критерий готовности новичка

- собирает и проверяет проект без подсказок;
- объясняет поток «ход игрока → доска → счёт → вид»;
- ориентируется в форматах содержания и знает про переворот SGF;
- сделал изменение с тестом и прошёл `check.ps1`;
- знает, где смотреть решения и известные проблемы.
