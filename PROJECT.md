# Go Engine — манифест проекта

## Что это

Кроссплатформенная offline-игра Го (19×19, 13×13, 9×9) для Windows, macOS, Linux, iOS, Android.
Игрок против AI. Сложность AI — от 30 кю до 10 кю (цель первой версии).

**Текущий фактический уровень.** Без улучшений серии T-019a…T-019e движок играет на 20–15 кю:
MCTS с чистыми случайными playout'ами не даёт заявленной силы при реалистичных бюджетах
(`DECISIONS.md`, D-015, D-016). Серия T-019a…T-019e усиливает MCTS без нейросети;
потолок такой серии — 8–10 кю. Уровни 5 кю и выше — только во второй версии, с нейросетью (ONNX).

## Границы проекта

- **Offline-first.** Игра работает без интернета. Внешние зависимости не загружаются.
- **Один процесс.** Никаких серверов, никакой сети.
- **AI — внутри процесса.** MCTS, без нейросети в первой версии.
- **Кроссплатформенность.** Avalonia UI + SkiaSharp.

## Слои и зависимости

```
GoEngine.Core       ← ничего, кроме System.*
GoEngine.AI         ← только Core
GoEngine.App        ← Core, AI, Avalonia, SkiaSharp
GoEngine.AI.Onnx    ← Core, AI, ONNX Runtime (v2)
GoEngine.Tests      ← Core, AI, AI.Onnx, xUnit
```

Строгое правило: **слой не может ссылаться на слой выше себя**.

Интерфейс разделён на библиотеку и головы: `GoEngine.App` — библиотека (виды, модель
представления, сервисы, рисование), `GoEngine.App.Desktop` и `GoEngine.App.Android` — головы
с точкой входа и платформенными пакетами. Голова ссылается на библиотеку, библиотека на головы
не ссылается (`DECISIONS.md`, D-036).

| Слой | Может ссылаться на | Запрещено |
|---|---|---|
| `Core` | `System.*` | Avalonia, AI, IO, БД |
| `AI` | `Core`, `System.*` | Avalonia, IO, БД |
| `App` | `Core`, `AI`, Avalonia, SkiaSharp | — |
| `AI.Onnx` | `Core`, `AI`, ONNX Runtime | Avalonia, IO, БД |
| `Tests` | `Core`, `AI`, `AI.Onnx`, xUnit | `App` |

## Технологический стек

- .NET 8 (LTS)
- C# 12
- Avalonia UI 11.x (библиотека интерфейса — `Avalonia`, `Avalonia.Skia`, `Avalonia.Themes.Fluent`;
  `Avalonia.Desktop` — только в голове настольной версии, `Avalonia.Android` — только в голове Android)
- SkiaSharp (и `SkiaSharp.NativeAssets.Linux`: нативная библиотека Skia для Linux обязана
  совпадать по версии с управляемой, иначе сборка для Linux падает при запуске)
- Microsoft.Extensions.Logging и Microsoft.Extensions.Logging.Abstractions — логирование;
  провайдер записи в файл свой (`GoEngine.App/Services/Logging`), внешние не добавляются
- xUnit + Moq для тестов
- Microsoft.Extensions.TimeProvider.Testing — `FakeTimeProvider` в тестах AI (только тесты)
- Microsoft.ML.OnnxRuntime — нейросетевая оценка v2 (проект `GoEngine.AI.Onnx`)
- `System.CommandLine` — не используется
- Внешние пакеты — минимальны, только необходимые
- Версия пакета объявлена один раз — в `src/Directory.Packages.props`; в проектах
  `PackageReference` идёт без `Version` (Central Package Management)
- Модель KataGo лежит в `models/` и в индекс git не попадает (72 МБ): источник, лицензия,
  SHA-256 и команда скачивания — в `models/README.md`; без файла тесты модели пропускаются
  (`DECISIONS.md`, D-033)

## Что НЕ используется

- MediatR, AutoMapper, FluentValidation
- Entity Framework, Dapper, любые ORM
- ASP.NET Core, ASP.NET MVC
- Newtonsoft.Json (только `System.Text.Json`)
- Любые пакеты для Go — всё пишем сами

Пространства имён: у `Core` и `AI` — одно на проект (`GoEngine.Core`, `GoEngine.AI`): папки делят код
по областям, но пространство имён не дробят. У `App` namespace повторяет папку (`GoEngine.App.Views`,
`GoEngine.App.ViewModels`, …): на них ссылается XAML через `clr-namespace`. Правило закреплено
тестами `LayerBoundaryTests` (границы слоёв) и `NamespaceConventionTests` (пространства имён).

В `GoEngine.sln` проекты лежат двумя папками решения — `src` и `tests` — и идут по слоям
(`Core` → `AI` → `AI.Onnx` → `App` → `Tests` → `App.Tests`). Конфигурации — только
`Debug|Any CPU` и `Release|Any CPU`: сборки под системы задаются идентификатором `-r <rid>`.

В корне репозитория лежат документы-контракты (`GO_RULES.md`, `AGENTS.md`, `AGENTS_GO.md`,
`PROJECT.md`, `STATE.md`, `DECISIONS.md`, `GIT.md`, `PLAN.md`, папка `TASKS/`), скрипты
проверки и сборки, `.editorconfig` (правила редактора для документов и скриптов),
`.gitattributes` (LF во всех текстовых файлах), `global.json` (минимальная версия SDK)
и `.github/workflows/ci.yml`. Эти файлы не переезжают в подпапки: на них ссылаются правила
проекта и стартовый брифинг сессии.

Роли документов не пересекаются: `PLAN.md` — состав фаз и их итог, `TASKS/` — тексты задач,
`STATE.md` — единственный источник правды о статусах, `DECISIONS.md` — почему сделано так.

## Как проверять проект

- `./check.ps1` (Windows) или `./check.sh` (Linux, macOS) — полная проверка: сборка решения,
  оба тестовых проекта и все проверочные режимы приложения. Флаг `--skip-stress` пропускает
  проверку нагрузки.
- `./build.ps1` и `./build.sh` — то же плюс самодостаточные сборки под три системы в `artifacts/`.
- `.github/workflows/ci.yml` — та же проверка на сборочном агенте (Linux — `check.sh`,
  Windows — `check.ps1 -SkipStress`). Проверочные режимы не открывают окно, поэтому агент
  без графической сессии проходит их целиком.
- `.github/workflows/release.yml` — релиз по тегу `v*` или вручную из вкладки Actions:
  проверка проекта, затем самодостаточные сборки `win-x64`, `linux-x64`, `osx-x64`, `osx-arm64`
  и APK для Android, всё складывается в релиз на GitHub.
- `dotnet run --project src/GoEngine.App.Desktop` — запуск игры.

Проверочные режимы приложения не открывают окно, поэтому работают и на сборочном агенте:
`--smoke` (точка входа), `--check` (попадание щелчка в точку), `--state` (панель статуса и ход AI),
`--settings` (файл настроек), `--sgf` (круговорот партии), `--animation` (кадры анимации),
`--e2e` (полный сценарий партии), `--stress` (сто партий, память), `--render` и `--render-anim`
(кадр доски и кадр анимации в PNG), `--problems` (режим задач: вид задачи, линия источника и отказ
постороннего хода — идёт через ту же модель, что и вид, поэтому проверяет всё, кроме пикселей),
`--result` (строки итога партии: «Вы победили» и «Вы проиграли» — то, что видит игрок после партии).

Отдельно — `--crash-test`: пишет несколько событий в лог и **намеренно падает**, чтобы проверить
лог падений. В `check.ps1` он не входит: проверка проекта требует нулевого кода возврата, а этот
режим по замыслу завершается сбоем. Запускают вручную:

```powershell
dotnet run --project src/GoEngine.App.Desktop -- --crash-test
```


### Обход, если `dotnet test` не стартует

В некоторых средах хост тестов падает на старте с `Win32Exception (5)` в `Process.EnsureWatchingForExit`
(«Отказано в доступе»): он не может открыть родительский процесс и умирает, не выполнив ни одного теста.
Тогда те же тесты прогоняет утилита `src/GoEngine.Tools.TestRunner` — она запускает xunit напрямую, без vstest:

```powershell
dotnet build src/GoEngine.Tools.TestRunner/TestRunner.csproj
dotnet run --project src/GoEngine.Tools.TestRunner/TestRunner.csproj --no-build -- src/GoEngine.Tests/bin/Debug/net8.0/GoEngine.Tests.dll
```

Второй аргумент — подстрока имени теста для отбора (необязательный). Утилита не входит в `GoEngine.sln`
и частью продукта не является; в CI её можно собрать отдельно (`tools/` в репозиторий не коммитится). Две вещи, без которых она не работает и которые стоит помнить:
культура процесса должна быть инвариантной (иначе строки счёта расходятся с ожиданиями тестов),
а нативные библиотеки Skia находятся в каталоге тестовой сборки — утилита подкладывает их сама.
Ещё одна граница среды: запись во временный каталог пользователя бывает запрещена, поэтому прогон
идёт с `TEMP`, переведённым в `artifacts/test-temp`.

После него в каталоге логов появляются копия `crash-ГГГГММДД-ЧЧММСС.log` и файл-признак
`ПОСЛЕДНИЙ_СБОЙ.txt`; следующий запуск показывает в настройках сообщение о сбое и путь к копии,
после чего признак удаляется — сообщение не висит вечно, а копия остаётся для отправки.

## Логи и падения

Логи пишутся в файл в каталоге пользователя, по одному на сутки (`goengine-ГГГГММДД.log`), части
при превышении размера — `…-2.log`, хранение — 7 дней. Каталог: Windows `%AppData%\GoEngine\logs`,
Linux `~/.config/goengine/logs`, macOS `~/Library/Logs/GoEngine`; на Android — личные файлы
приложения. Путь и кнопка «Открыть папку с логами» есть в настройках.

Провайдер записи — свой (`Services/Logging`), поверх `Microsoft.Extensions.Logging`; внешние
провайдеры вроде Serilog не добавляются. Логирование не имеет права уронить игру: ошибки записи
молча пропускаются, а состояние видно в настройках.

Если игра упала, игрок присылает файл `crash-….log` из каталога логов (путь показан в настройках
после сбоя). В нём — версия сборки, система, события партии, полная цепочка исключений и стек.

## Обновления

Каждый push в `main` публикует **версионированный выпуск** `v<версия>` и обновляет плавающий
релиз `latest` (`.github/workflows/latest.yml`). Версия — `0.2.<номер прогона>`: номер прогона
в GitHub только растёт, поэтому тег не повторяется и не понижается. Версия попадает внутрь сборок
(`-p:Version` для .NET, `ApplicationDisplayVersion` и растущий `ApplicationVersion` для Android),
поэтому приложение знает свою версию и умеет сравнивать её с выпуском.

**Два канала и зачем оба.** Версионированный тег неизменяем: приложение скачивает файл по его
ссылке, и файл не подменится под руками у игрока. Плавающий `latest` даёт постоянные адреса —
приложение заранее знает, где искать манифест, и этот адрес не переписывается под каждый выпуск.

**Манифест обновления `update.json`** публикуется в обоих каналах (в `latest` — всегда свежий,
в версии — тот, что был на момент выпуска). Его собирает `.github/scripts/make-update-manifest.py`
при публикации: размеры и SHA-256 считаются по фактическим файлам. Формат — публичный контракт,
его читает `GoEngine.App.Services.Updates.UpdateManifest`:

```json
{
  "version": "0.2.15",
  "tag": "v0.2.15",
  "publishedAt": "2026-09-28T12:00:00Z",
  "commit": "…",
  "assets": {
    "win-x64":   { "name": "GoEngine-Setup.exe", "url": "https://…/releases/download/v0.2.15/GoEngine-Setup.exe", "size": 154800000, "sha256": "…" },
    "android":   { "name": "com.goengine.app-Signed.apk", "url": "…", "size": 135800000, "sha256": "…" },
    "linux-x64": { "name": "go-engine-linux-x64.tar.gz", "url": "…", "size": 110200000, "sha256": "…" },
    "osx-x64":   { "name": "go-engine-osx-x64.tar.gz", "url": "…", "size": 114900000, "sha256": "…" },
    "osx-arm64": { "name": "go-engine-osx-arm64.tar.gz", "url": "…", "size": 112200000, "sha256": "…" }
  }
}
```

**Что делает приложение.** Экран настроек показывает версию и кнопку «Проверить обновления»:
проверка читает манифест по адресу `releases/download/latest/update.json` и сравнивает версии
(`UpdateChecker`). Если выпуск новее, появляется кнопка «Скачать и установить»: файл скачивается,
проверяется по размеру и SHA-256 (`UpdateDownloader`), и только потом передаётся установщику
платформы (`IUpdateInstaller`). Установка честно различается по системам:

| Система | Что происходит |
|---|---|
| Windows | `GoEngine-Setup.exe` запускается тихо (`/SILENT /SUPPRESSMSGBOXES /NORESTART`), приложение обновляется поверх прежнего |
| Android | APK отдаётся системному установщику через `FileProvider` (нужны разрешения `INTERNET` и `REQUEST_INSTALL_PACKAGES`), игрок подтверждает установку |
| Linux, macOS | архив скачивается и проверяется, открывается папка с файлом: заменить работающее приложение приложение не может и не делает вид, что может |

Сетевые ошибки, таймаут и битый манифест — ожидаемые исходы (`Result`), а не падения: без интернета
игра работает как обычно, а на экране настроек появляется причина отказа по-русски.
